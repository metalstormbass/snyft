## Maintainer Responsibilities

Maintainers are responsible for:

1. **Code Review**
   - Review pull requests for code quality, security, and design
   - Provide constructive feedback to contributors
   - Ensure tests pass and code coverage is maintained

2. **Issue Triage**
   - Label and prioritize incoming issues
   - Respond to bug reports and feature requests
   - Close stale or duplicate issues

3. **Release Management**
   - Coordinate release timing
   - Update changelog and version numbers
   - Create release tags and GitHub releases
   - Announce releases to the community

4. **Security Response**
   - Respond to security vulnerability reports
   - Coordinate security patches
   - Publish security advisories

5. **Community Support**
   - Answer questions in issues and discussions
   - Welcome new contributors
   - Maintain CODE_OF_CONDUCT adherence

6. **Documentation**
   - Keep documentation up-to-date
   - Review documentation contributions
   - Ensure architecture documentation reflects reality

## Becoming a Maintainer

We welcome additional maintainers to help scale the project! The process to become a maintainer:

### Criteria

- Consistent, high-quality contributions over 3+ months
- Deep understanding of the codebase and architecture
- Demonstrated commitment to code quality and testing
- Active participation in code reviews and discussions
- Alignment with project values and goals
- Respectful and collaborative communication style

### Process

1. **Nomination:** Existing maintainers may nominate contributors, or contributors may self-nominate
2. **Discussion:** Maintainers discuss the nomination privately
3. **Consensus:** Decision made by consensus among existing maintainers
4. **Invitation:** Nominee is invited to become a maintainer
5. **Onboarding:** New maintainer is granted repository access and onboarded

## Maintainer Succession

To ensure project continuity:

- If a maintainer becomes inactive (no activity for 6+ months), we'll reach out to confirm their status
- Inactive maintainers may be moved to "Emeritus Maintainers" section
- Emeritus maintainers can be reinstated if they return to active participation
- Repository ownership should transfer to an organization if/when the project grows

## Decision Making

### Routine Decisions
- Made by individual maintainers (e.g., merging small PRs, labeling issues)
- Use best judgment aligned with project goals

### Significant Decisions
- Breaking changes, major features, architecture changes
- Require discussion and consensus among maintainers
- Use GitHub Discussions or issues for transparent decision-making
- If consensus cannot be reached, lead maintainer makes final decision

### Emergency Decisions
- Security vulnerabilities, critical bugs, outages
- Lead maintainer or most available maintainer makes rapid decisions
- Inform other maintainers as soon as possible

## Maintainer Expectations

### Time Commitment
- No fixed time requirement, but regular participation expected
- Respond to @mentions within 1 week when possible
- Coordinate absences (vacations, busy periods) with other maintainers

### Code of Conduct
- Maintainers are held to the highest standards of conduct
- Be respectful, inclusive, and patient with contributors
- Assume good intent and provide constructive feedback
- Address Code of Conduct violations promptly and fairly

### Conflict of Interest
- Disclose conflicts of interest (employer interests, competing projects)
- Recuse yourself from decisions where you have a conflict
